System Requirements

System Requirements

This page covers the hardware, software, and network requirements for running the various components of the Bracken protocol: ciphernodes, compute providers, and development environments.

Ciphernode Requirements

A ciphernode participates in threshold cryptography (DKG, decryption) and generates zero-knowledge proofs. The workload is CPU and memory intensive, especially during DKG and proof generation.

Minimum (Development / Testnet)

ComponentSpecification
CPU4+ modern cores (x86-64)
RAM16 GB
Disk100 GB SSD
NetworkStable broadband, UDP port open for QUIC

Recommended (Production / Mainnet)

ComponentSpecification
CPU8+ modern cores (x86-64, AVX2)
RAM32 GB DDR5 (or DDR4 ECC)
Disk500 GB NVMe SSD
NetworkLow-latency broadband, unfiltered UDP

Operating System

PlatformStatus
Linux✅ Fully supported (x86_64)
macOS✅ Supported (Apple Silicon)
Windows⚠️ Via WSL2 or Docker

Note: The Linux binary is the primary target. macOS Apple Silicon binaries are available. Windows users should use WSL2 or the Docker image.

Software Dependencies

DependencyMinimum VersionPurpose
Bracken CLILatest releaseNode management and CLI operations
Rust1.91.1+Building from source
WebSocket RPC—Real-time event listening (wss:// URL)

Network Requirements

  • QUIC port: UDP must be unfiltered. Default QUIC port is set in your config (bracken.config.yaml). Cloud firewalls (AWS Security Groups, GCP firewall rules) must allow UDP inbound on this port.
  • WebSocket RPC: The node subscribes to on-chain events via WebSocket. An HTTP-only RPC endpoint will fall back to polling and may miss events. Always use a wss:// URL.
  • NAT: If behind NAT, configure port forwarding for the QUIC UDP port.

Disk Usage

DataTypical Size
Node state10–50 GB
Circuit artifacts5–15 GB
Logs1–10 GB (rotated)
Total (baseline)30–100 GB

Provision at least 500 GB to accommodate growth, log retention, and multiple networks. Use SSD storage — spinning disks may cause missed submission windows under I/O load.

Compute Provider Requirements

Running a compute provider (e.g., RISC Zero with Boundless) requires additional resources beyond the ciphernode baseline.

RISC Zero / Boundless

ComponentSpecification
CPU16+ cores (more is better)
RAM64 GB+
Disk200 GB+ SSD
GPUNot required (CPU proving only)

For production proving, Boundless offloads proof generation to a decentralized market. Local resources are only needed for development and testing.

Resource Scaling Guide

WorkloadCPURAMNotes
Idle ciphernode1–22–4 GBJust listening for events
DKG (N=3, L=2)4–88–16 GBInsecure preset, local dev
DKG (N=5, L=4)8–1624–32 GBSecure preset, production
ZK proof gen peakAll cores28–32 GBMemory spikes during C3 proofs
Compute provider8–3232–64 GBDepends on FHE program complexity

Memory tip: If your node starts OOM-killing during DKG, this is a resource constraint, not a software bug. Add more RAM or reduce parallelism settings.

Monitoring Resource Usage

Use the embedded dashboard to monitor node health. For system-level monitoring:

# Check memory usage
free -h
 
# Monitor CPU and memory per process
htop
 
# Check disk usage
df -h
 
# Monitor network connections (QUIC uses UDP)
ss -ulnp | grep <quic_port>
