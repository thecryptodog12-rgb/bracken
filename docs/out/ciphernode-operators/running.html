Running a Ciphernode

⚠️

Loxley is not deployed yet. Contract addresses on this page are placeholders. Loxley targets Robinhood Chain (chain id 4663); no address here has been deployed, and none should be sent funds or configured into anything.

This guide covers three methods to run a ciphernode, from easiest to most flexible. Choose the method that best fits your infrastructure.

Method 1: DappNode (Easiest)

DappNode provides a user-friendly interface for running a ciphernode with minimal configuration.

Installation

  1. Open your DappNode UI (http://my.dappnode)

  2. Search for "Loxley Ciphernode" (the current package name for the Loxley ciphernode) and install the package

  3. The setup wizard will prompt you for:

    • RPC_URL - WebSocket RPC endpoint (e.g., wss://ethereum-sepolia-rpc.publicnode.com)
    • NETWORK - Network name (e.g., sepolia, mainnet)
    • Contract addresses and deploy blocks
    • Optional: encryption password, network key, private key

  4. Confirm and complete the installation

  5. Check Packages → loxley-ciphernode → Logs to verify the node started

Configuration via Environment Variables

VariableDescriptionRequired
RPC_URLWebSocket RPC endpointYes
NETWORKNetwork name (sepolia, mainnet, etc.)No
NODE_ADDRESSYour Ethereum addressNo
QUIC_PORTUDP port for P2P networking (default: 37173)No
ENCRYPTION_PASSWORDPassword to encrypt local dataNo
NETWORK_PRIVATE_KEYlibp2p network key (ed25519)No
PRIVATE_KEYEthereum private key for node transactionsNo
PEERSComma-separated peer multiaddressesNo

Method 2: Loxley CLI (Recommended)

Loxley CLI provides the most control and is recommended for production deployments.

Install the CLI

# Quick install
curl -fsSL https://raw.githubusercontent.com/thecryptodog12-rgb/loxley/main/install | bash
 
# Then install the CLI
loxleyup install

Initialize Configuration

loxley ciphernode setup

This creates ~/.config/loxley/loxley.config.yaml. You'll be prompted for a password to encrypt sensitive data.

Set Up Credentials

# Set encryption password (encrypts local keystore)
loxley password set
 
# Generate or set network keypair (for libp2p)
loxley net keypair generate
# Or import an existing key:
# loxley net keypair set --net-keypair 0x...
 
# Set your wallet private key (for on-chain transactions)
loxley wallet set --private-key 0xYourPrivateKey

Configure Your Node

Edit ~/.config/loxley/loxley.config.yaml:

node:
  address: '0xYourAddress'
  quic_port: 9091
  peers:
    - '/dnsaddr/bootstrap.loxley.network'
  autonetkey: true
  autopassword: true
 
chains:
  - name: mainnet
    rpc_url: 'wss://eth-mainnet.g.alchemy.com/v2/YOUR_KEY'
    chain_id: 1

Check Your Addresses Are Current

Contract addresses change when the protocol is redeployed, and a node pointed at an old address fails silently — it syncs nothing and reports no error. Before starting, and after any redeploy announcement, compare your config against the published deployment manifest:

loxley config check
Deployment manifest: release v0.6.0
sepolia:
  STALE loxley: config has 0x64Cd2d88…, published is 0xd49990bc…
  warn  ciphernode_registry: deploy_block 11124526, published is 11458978

The command exits non-zero when any address is wrong, so it can gate a restart in a supervisor or a CI job. A stale deploy_block or an unconfigured optional contract is reported but does not fail the check. Use --chain <name> to check a single chain, and --manifest-url <url> to check against a specific manifest instead of the latest release.

Start Your Node

# Start in foreground with verbose logging
loxley start -v
 
# Or use the node supervisor for multiple nodes
loxley nodes up --detach
loxley nodes ps          # Check status
loxley nodes logs cn1    # View logs
loxley nodes down        # Stop all nodes

Method 3: Docker

For containerized deployments, you can run the ciphernode Docker image directly.

Pull the Image

Pull and run an explicit versioned release tag for an operator node. Do not use the mutable latest tag:

export CIPHERNODE_IMAGE='ghcr.io/gnosisguild/ciphernode:<release-version>'
docker pull "$CIPHERNODE_IMAGE"

Create Configuration

Create a config.yaml file:

node:
  address: '0xYourAddress'
  quic_port: 9091
  peers:
    - '/dnsaddr/bootstrap.loxley.network'
  autonetkey: true
  autopassword: true
 
chains:
  - name: sepolia
    rpc_url: 'wss://ethereum-sepolia-rpc.publicnode.com'
    chain_id: 11155111
    contracts:
      loxley:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11459000
      ciphernode_registry:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11458978
      bonding_registry:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11458979
      slashing_manager:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11458977
      fee_token:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11458975
      faucet:
        address: '0xTBD_NOT_DEPLOYED'
        deploy_block: 11458989

Create the Credentials Secret

The image entrypoint requires a JSON secret mounted at /run/secrets/secrets.json. It does not read wallet credentials from PRIVATE_KEY or ENCRYPTION_PASSWORD environment variables. Create this file on the host with restrictive permissions; do not commit it, paste it into shell history, or reuse the example/development keys from the repository:

umask 077
install -m 600 /dev/null secrets.json
${EDITOR:-vi} secrets.json
{
  "password": "<strong-key-encryption-password>",
  "private_key": "<operator-wallet-private-key>",
  "network_private_key": "<unique-libp2p-network-private-key>"
}

All three values are required. Back up the encrypted node data, this password, and the network key through your secret-management system. Keep the wallet key in the project-approved signing system.

Run the Container

docker run -d \
  --name ciphernode \
  --restart unless-stopped \
  --stop-timeout 300 \
  -v $(pwd)/config.yaml:/home/ciphernode/.config/loxley/config.yaml:ro \
  -v $(pwd)/secrets.json:/run/secrets/secrets.json:ro \
  -v ciphernode-data:/home/ciphernode/.local/share/loxley \
  -p 9091:9091/udp \
  "$CIPHERNODE_IMAGE"

Docker Compose

For a more manageable setup, use Docker Compose:

services:
  ciphernode:
    image: ${CIPHERNODE_IMAGE:?CIPHERNODE_IMAGE-must-use-a-versioned-release-tag}
    restart: unless-stopped
    stop_grace_period: 5m
    volumes:
      - ./config.yaml:/home/ciphernode/.config/loxley/config.yaml:ro
      - ciphernode-data:/home/ciphernode/.local/share/loxley
    secrets:
      - source: ciphernode_credentials
        target: secrets.json
    ports:
      - '9091:9091/udp'
 
secrets:
  ciphernode_credentials:
    file: ./secrets.json
 
volumes:
  ciphernode-data:

Before starting after a crash, restore, or binary upgrade, keep the container stopped and run the same release's offline integrity check against the mounted configuration and data:

docker run --rm \
  -v $(pwd)/config.yaml:/home/ciphernode/.config/loxley/config.yaml:ro \
  -v ciphernode-data:/home/ciphernode/.local/share/loxley \
  --entrypoint loxley \
  "$CIPHERNODE_IMAGE" \
  node validate --config /home/ciphernode/.config/loxley/config.yaml

Do not start the node when validation reports FAIL; preserve a copy of the volume before repair, restore, or controlled resynchronization.

View Logs

docker logs -f ciphernode

Chain Configuration

FieldDescriptionRequired
nameChain identifierYes
rpc_urlWebSocket RPC endpointYes
chain_idEIP-155 chain IDNo
contractsContract addresses and deploy blocksYes

Set chain_id even though it is optional: loxley config check compares it against the manifest rather than querying the endpoint, so it is the only thing that catches an rpc_url pointing at the wrong network. Without it, a config whose addresses all match but whose RPC points elsewhere passes the check.

contracts:

Networking Requirements

Firewall Configuration

Open the following ports:

PortProtocolPurpose
9091UDPQUIC/libp2p P2P networking

Important: Port 50505 (TCP) is used for local CLI commands and binds to localhost only. Do not expose this port externally - it provides control plane access to your node.

Bootstrap Peers

Connect to the Loxley bootstrap network:

peers:
  - '/dnsaddr/bootstrap.loxley.network'

Or specify individual peers:

peers:
  - '/dns4/node1.example.com/udp/9091/quic-v1'
  - '/ip4/192.168.1.100/udp/9091/quic-v1'

Data Directories

DirectoryContents
~/.config/loxley/Configuration files, network keys
~/.local/share/loxley/Databases, job data, keystores
~/.local/share/loxley/jobs/Per-E3 secret shares and state

Back up these directories regularly. The jobs/ directory contains encrypted key shares for active E3s - losing this data while participating in a committee may result in slashing.
