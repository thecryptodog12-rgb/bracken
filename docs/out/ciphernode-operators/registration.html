Registration & Bonding

This guide walks you through the complete registration process to become an active ciphernode operator. Make sure your node is already running before proceeding.

Interactive alternative: the dashboard can do every step on this page in your browser. It shows the live bond size, ticket price, and operator status, and it sends each transaction from the connected wallet. Open Run a ciphernode (opens in a new tab). The commands below remain the reference path for automated or headless setups.

Prerequisites

Registration supports one or two wallets:

  • The operator key runs the node and authorizes its initial bond owner.
  • The bond owner holds BRACKEN and the ticket collateral token. It controls the position lifecycle.

Using a separate cold wallet or Safe as the bond owner is strongly recommended so the running node does not hold the key controlling collateral. Self-ownership is supported if an operator prefers a single-wallet setup. Ensure the selected bond-owner wallet has:

TokenAmount RequiredPurpose
BRACKENMainnet: 32,000 BRACKENCiphernode bond collateral
sUSDSMainnet: 1,000 sUSDS shares per ticketTicket balance for sortition
ETHSufficient for gasTransaction fees

Testnet tokens: on Sepolia you can self-serve test BRACKEN and mock USDC from the faucet with bracken faucet (requires the faucet contract address in your config — see Running a Node → Contract Addresses). Each call tops up BRACKEN and the fee token independently, only when your balance for that token is below the faucet threshold. One call dispenses enough BRACKEN to meet the default Sepolia ciphernode bond. If the faucet runs dry, open an issue (opens in a new tab).

Registration Steps

Step 1: Check Current Status

First, verify your current on-chain status:

bracken ciphernode status

Example output:

Ciphernode status on mainnet:
  Operator key: 0x70997970C51812dc3A010C7d01b50e0d17dc79C8
  Bond owner: not configured
  Registered: false
  Active: false
  Exit pending: false
  Ticket balance: 0 (0 available)
  Ciphernode bond: 0
  Pending exits: tickets=0, bond=0
  Requirements: minTickets=1, ticketPrice=1000 tBRACKEN, ciphernodeBond=32000 BRACKEN

Step 2: Authorize the Bond Owner

From the node's operator key, authorize the wallet or Safe that will control collateral:

bracken ciphernode set-bond-owner --owner 0xBOND_OWNER

The owner must be nonzero and may equal the operator address, although a separate cold wallet or Safe is recommended. The operator can correct the address before the position is funded. Once it holds collateral or is registered, owner changes use the two-step proposal and acceptance flow described below.

Step 3: Fund and Register the Operator

For an EOA bond owner, run the owner-aware CLI commands using a config whose encrypted signer is that owner:

bracken --config /path/to/owner.yaml ciphernode bond \
  --operator 0xOPERATOR bond --amount 32000
bracken --config /path/to/owner.yaml ciphernode register --operator 0xOPERATOR
bracken --config /path/to/owner.yaml ciphernode tickets \
  --operator 0xOPERATOR buy --amount 1000

The CLI submits any required token approval first. Safe owners can submit the same bondCiphernodeFor, registerOperatorFor, and addTicketBalanceFor calls through the Safe interface. The owner supplies the assets, while the operator address is added to the registry Merkle tree and receives non-transferable tBRACKEN. With the recommended separate-owner setup, the hot operator key does not control BRACKEN or ticket collateral withdrawals, and protocol rewards are credited to the bond owner.

The number of usable tickets is calculated as:

availableTickets = floor(ticketTokenBalance / ticketPrice)

With a ticket price of 1,000 sUSDS shares and a 1,000 sUSDS share deposit, you get one available ticket.

Step 4: Verify Active Status

Confirm your registration is complete:

bracken ciphernode status

Expected output for an active operator:

Ciphernode status on mainnet:
  Operator key: 0x70997970C51812dc3A010C7d01b50e0d17dc79C8
  Bond owner: 0xBOND_OWNER
  Registered: true
  Active: true
  Exit pending: false
  Ticket balance: 1000 (1 available)
  Ciphernode bond: 32000
  Pending exits: tickets=0, bond=0
  Requirements: minTickets=1, ticketPrice=1000 tBRACKEN, ciphernodeBond=32000 BRACKEN

Operator CLI Commands

# Authorize the bond owner from the hot operator key
bracken ciphernode set-bond-owner --owner 0xBOND_OWNER
 
# Fund and register from an EOA bond-owner config
bracken --config /path/to/owner.yaml ciphernode bond \
  --operator 0xOPERATOR bond --amount 32000
bracken --config /path/to/owner.yaml ciphernode register --operator 0xOPERATOR
bracken --config /path/to/owner.yaml ciphernode tickets \
  --operator 0xOPERATOR buy --amount 1000
 
# The owner or operator can stop participation
bracken ciphernode deregister --operator 0xOPERATOR
 
# Check status
bracken ciphernode status --operator 0xOPERATOR

Omit --operator for a self-owned position. In the recommended two-wallet setup, run financial commands with the bond-owner config and pass the node's operator address explicitly.

Activation Controls

Two commands adjust the activation state of an operator without a full exit:

# Register an operator again after a full exit
bracken --config /path/to/owner.yaml ciphernode activate --operator 0xOPERATOR
 
# Queue collateral for exit and drop below the active thresholds
bracken --config /path/to/owner.yaml ciphernode deactivate \
  --operator 0xOPERATOR --tickets 50 --bond 25

activate sends the same registration call as register. Use it only to register an operator again after a deregister. The call reverts with AlreadyRegistered for an operator that is still registered.

To restore the active status of a registered operator after an eligibility parameter changes on-chain, call refreshOperatorStatus(operator) on the BondingRegistry. The call is permissionless. The CLI has no command for it.

deactivate requires --tickets, --bond, or both. It calls removeTicketBalanceFor for the ticket amount and unbondCiphernodeFor for the ciphernode bond amount. Both amounts enter the exit queue and become claimable after the exit delay. The operator stays registered, so use deregister for a full exit.

Rotate the Bond Owner

The current owner proposes a replacement, then the new owner accepts:

bracken --config /path/to/current-owner.yaml ciphernode propose-bond-owner \
  --operator 0xOPERATOR --new-owner 0xNEW_OWNER
bracken --config /path/to/new-owner.yaml ciphernode accept-bond-owner \
  --operator 0xOPERATOR

Active and pending BRACKEN ownership accounting moves atomically on acceptance. The operator key is not involved in rotation.

Multi-Chain Support

Specify a chain when operating on multiple networks:

bracken ciphernode status --chain mainnet
bracken ciphernode set-bond-owner --owner 0xBOND_OWNER --chain sepolia

The --chain parameter matches the name field in your config's chains array.

Best Practices

Maintain Buffer Amounts

  • Ciphernode bond: Keep 10-20% above the minimum to absorb potential slashing without losing active status
  • Tickets: Maintain extra tickets so you're not deactivated if one is consumed or slashed

Monitor Your Status

Set up alerts for:

  • isActive changing to false
  • SlashProposed events targeting your address
  • Low ticket balance approaching minimum

Monitor Activation Events

Watch for OperatorActivationChanged events targeting your address. These fire whenever your active status changes due to balance or bond updates.
