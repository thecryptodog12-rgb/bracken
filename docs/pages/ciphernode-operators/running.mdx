# Running a Ciphernode

<Callout type='info'>
  **Bracken is live on Robinhood Chain** (chain id `4663`). Any address shown inline below is an
  example unless it appears on [Deployments](/deployments) — that page is generated from the
  deployment record and is the one to configure against.
</Callout>

This guide covers three methods to run a ciphernode, from easiest to most flexible. Choose the
method that best fits your infrastructure.

## Method 1: DappNode (Easiest)

DappNode provides a user-friendly interface for running a ciphernode with minimal configuration.

### Installation

1. Open your DappNode UI (`http://my.dappnode`)
2. Search for **"Bracken Ciphernode"** (the current package name for the Bracken ciphernode) and
   install the package
3. The setup wizard will prompt you for:
   - `RPC_URL` - WebSocket RPC endpoint (e.g., `wss://ethereum-sepolia-rpc.publicnode.com`)
   - `NETWORK` - Network name (e.g., `sepolia`, `mainnet`)
   - Contract addresses and deploy blocks
   - Optional: encryption password, network key, private key

4. Confirm and complete the installation
5. Check **Packages → bracken-ciphernode → Logs** to verify the node started

### Configuration via Environment Variables

| Variable              | Description                                  | Required |
| --------------------- | -------------------------------------------- | -------- |
| `RPC_URL`             | WebSocket RPC endpoint                       | Yes      |
| `NETWORK`             | Network name (sepolia, mainnet, etc.)        | No       |
| `NODE_ADDRESS`        | Your Ethereum address                        | No       |
| `QUIC_PORT`           | UDP port for P2P networking (default: 37173) | No       |
| `ENCRYPTION_PASSWORD` | Password to encrypt local data               | No       |
| `NETWORK_PRIVATE_KEY` | libp2p network key (ed25519)                 | No       |
| `PRIVATE_KEY`         | Ethereum private key for node transactions   | No       |
| `PEERS`               | Comma-separated peer multiaddresses          | No       |

## Method 2: Bracken CLI (Recommended)

Bracken CLI provides the most control and is recommended for production deployments.

### Install the CLI

```bash
# Quick install
curl -fsSL https://raw.githubusercontent.com/thecryptodog12-rgb/bracken/main/install | bash

# Then install the CLI
brackenup install
```

### Initialize Configuration

```bash
bracken ciphernode setup
```

This creates `~/.config/bracken/bracken.config.yaml`. You'll be prompted for a password to encrypt
sensitive data.

### Set Up Credentials

```bash
# Set encryption password (encrypts local keystore)
bracken password set

# Generate or set network keypair (for libp2p)
bracken net keypair generate
# Or import an existing key:
# bracken net keypair set --net-keypair 0x...

# Set your wallet private key (for on-chain transactions)
bracken wallet set --private-key 0xYourPrivateKey
```

### Configure Your Node

Edit `~/.config/bracken/bracken.config.yaml`:

```yaml
node:
  address: '0xYourAddress'
  quic_port: 9091
  peers:
    - '/dnsaddr/bootstrap.bracken.network'
  autonetkey: true
  autopassword: true

chains:
  - name: robinhood
    rpc_url: 'https://rpc.mainnet.chain.robinhood.com'
    chain_id: 4663
    contracts:
      bracken:
        address: '0xB2719FBF71F723FAb7fEAa1f3D2B6F23530AeE12'
        deploy_block: 45075164
      ciphernode_registry:
        address: '0x7d6e460B1704B5B1cd5570E62a3c450a9611C346'
        deploy_block: 45074710
      bonding_registry:
        address: '0x54921442e3f4272A899D6b647efB18f761a12CF6'
        deploy_block: 45074900
      slashing_manager:
        address: '0xd6f9AeEF1d419c5F2722157b73e2a4faBCd80d42'
        deploy_block: 45074623
      fee_token:
        address: '0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168'
        deploy_block: 45074406
```

### Check Your Addresses Are Current

Contract addresses change when the protocol is redeployed, and a node pointed at an old address
fails silently — it syncs nothing and reports no error. Before starting, and after any redeploy
announcement, compare your config against the published deployment manifest:

```bash
bracken config check
```

```
Deployment manifest: release v0.6.0
sepolia:
  STALE bracken: config has 0x64Cd2d88…, published is 0xd49990bc…
  warn  ciphernode_registry: deploy_block 11124526, published is 11458978
```

The command exits non-zero when any address is wrong, so it can gate a restart in a supervisor or a
CI job. A stale `deploy_block` or an unconfigured optional contract is reported but does not fail
the check. Use `--chain <name>` to check a single chain, and `--manifest-url <url>` to check against
a specific manifest instead of the latest release.

### Start Your Node

```bash
# Start in foreground with verbose logging
bracken start -v

# Or use the node supervisor for multiple nodes
bracken nodes up --detach
bracken nodes ps          # Check status
bracken nodes logs cn1    # View logs
bracken nodes down        # Stop all nodes
```

### CLI Commands Reference

| Command                        | Description                                         |
| ------------------------------ | --------------------------------------------------- |
| `bracken start`                | Start the node in foreground                        |
| `bracken start -v`             | Start with INFO logging (`-vv`=DEBUG, `-vvv`=TRACE) |
| `bracken nodes up`             | Start all configured nodes                          |
| `bracken nodes up --detach`    | Start all nodes in background                       |
| `bracken nodes up --exclude x` | Start all nodes except `x`                          |
| `bracken nodes down`           | Stop all nodes                                      |
| `bracken nodes ps`             | List running nodes and their status                 |
| `bracken nodes start <name>`   | Start an individual node                            |
| `bracken nodes stop <name>`    | Stop an individual node                             |
| `bracken nodes status <name>`  | Check specific node status                          |
| `bracken nodes restart <name>` | Restart a specific node                             |
| `bracken nodes purge`          | Purge all local ciphernode data                     |
| `bracken ciphernode status`    | Show on-chain registration status                   |
| `bracken config check`         | Compare configured addresses against the manifest   |
| `bracken net get-peer-id`      | Show your libp2p peer ID                            |
| `bracken wallet get`           | Show your wallet address                            |
| `bracken rev`                  | Show the git SHA the CLI was built from             |
| `bracken purge-all`            | Wipe all local data (use with caution)              |
| `bracken print-env`            | Print contract addresses as env vars                |
| `bracken print-env --vite`     | Print env vars with `VITE_` prefix                  |
| `bracken print-env --chain x`  | Print env vars for chain `x`                        |
| `bracken noir status`          | Check ZK prover status                              |
| `bracken noir setup`           | Install/update ZK prover components                 |

## Method 3: Docker

For containerized deployments, you can run the ciphernode Docker image directly.

### Pull the Image

Pull and run an explicit versioned release tag for an operator node. Do not use the mutable `latest`
tag:

```bash
export CIPHERNODE_IMAGE='ghcr.io/gnosisguild/ciphernode:<release-version>'
docker pull "$CIPHERNODE_IMAGE"
```

### Create Configuration

Create a `config.yaml` file:

```yaml
node:
  address: '0xYourAddress'
  quic_port: 9091
  peers:
    - '/dnsaddr/bootstrap.bracken.network'
  autonetkey: true
  autopassword: true

chains:
  - name: robinhood
    rpc_url: 'https://rpc.mainnet.chain.robinhood.com'
    chain_id: 4663
    contracts:
      bracken:
        address: '0xB2719FBF71F723FAb7fEAa1f3D2B6F23530AeE12'
        deploy_block: 45075164
      ciphernode_registry:
        address: '0x7d6e460B1704B5B1cd5570E62a3c450a9611C346'
        deploy_block: 45074710
      bonding_registry:
        address: '0x54921442e3f4272A899D6b647efB18f761a12CF6'
        deploy_block: 45074900
      slashing_manager:
        address: '0xd6f9AeEF1d419c5F2722157b73e2a4faBCd80d42'
        deploy_block: 45074623
      fee_token:
        address: '0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168'
        deploy_block: 45074406
```

### Create the Credentials Secret

The image entrypoint requires a JSON secret mounted at `/run/secrets/secrets.json`. It does not read
wallet credentials from `PRIVATE_KEY` or `ENCRYPTION_PASSWORD` environment variables. Create this
file on the host with restrictive permissions; do not commit it, paste it into shell history, or
reuse the example/development keys from the repository:

```bash
umask 077
install -m 600 /dev/null secrets.json
${EDITOR:-vi} secrets.json
```

```json
{
  "password": "<strong-key-encryption-password>",
  "private_key": "<operator-wallet-private-key>",
  "network_private_key": "<unique-libp2p-network-private-key>"
}
```

All three values are required. Back up the encrypted node data, this password, and the network key
through your secret-management system. Keep the wallet key in the project-approved signing system.

### Run the Container

```bash
docker run -d \
  --name ciphernode \
  --restart unless-stopped \
  --stop-timeout 300 \
  -v $(pwd)/config.yaml:/home/ciphernode/.config/bracken/config.yaml:ro \
  -v $(pwd)/secrets.json:/run/secrets/secrets.json:ro \
  -v ciphernode-data:/home/ciphernode/.local/share/bracken \
  -p 9091:9091/udp \
  "$CIPHERNODE_IMAGE"
```

### Docker Compose

For a more manageable setup, use Docker Compose:

```yaml
services:
  ciphernode:
    image: ${CIPHERNODE_IMAGE:?CIPHERNODE_IMAGE-must-use-a-versioned-release-tag}
    restart: unless-stopped
    stop_grace_period: 5m
    volumes:
      - ./config.yaml:/home/ciphernode/.config/bracken/config.yaml:ro
      - ciphernode-data:/home/ciphernode/.local/share/bracken
    secrets:
      - source: ciphernode_credentials
        target: secrets.json
    ports:
      - '9091:9091/udp'

secrets:
  ciphernode_credentials:
    file: ./secrets.json

volumes:
  ciphernode-data:
```

Before starting after a crash, restore, or binary upgrade, keep the container stopped and run the
same release's offline integrity check against the mounted configuration and data:

```bash
docker run --rm \
  -v $(pwd)/config.yaml:/home/ciphernode/.config/bracken/config.yaml:ro \
  -v ciphernode-data:/home/ciphernode/.local/share/bracken \
  --entrypoint bracken \
  "$CIPHERNODE_IMAGE" \
  node validate --config /home/ciphernode/.config/bracken/config.yaml
```

Do not start the node when validation reports `FAIL`; preserve a copy of the volume before repair,
restore, or controlled resynchronization.

### View Logs

```bash
docker logs -f ciphernode
```

## Configuration Reference

### Node Configuration

| Field          | Description                         | Default                  |
| -------------- | ----------------------------------- | ------------------------ |
| `address`      | Your Ethereum address               | Required                 |
| `quic_port`    | UDP port for QUIC/libp2p networking | `9091`                   |
| `peers`        | Bootstrap peer multiaddresses       | `[]`                     |
| `autopassword` | Auto-generate password if missing   | `false`                  |
| `autowallet`   | Auto-load wallet from environment   | `false`                  |
| `data_dir`     | Override data directory             | `~/.local/share/bracken` |
| `config_dir`   | Override config directory           | `~/.config/bracken`      |

### Chain Configuration

| Field       | Description                          | Required |
| ----------- | ------------------------------------ | -------- |
| `name`      | Chain identifier                     | Yes      |
| `rpc_url`   | WebSocket RPC endpoint               | Yes      |
| `chain_id`  | EIP-155 chain ID                     | No       |
| `contracts` | Contract addresses and deploy blocks | Yes      |

Set `chain_id` even though it is optional: `bracken config check` compares it against the manifest
rather than querying the endpoint, so it is the only thing that catches an `rpc_url` pointing at the
wrong network. Without it, a config whose addresses all match but whose RPC points elsewhere passes
the check.

### Contract Addresses

Each chain requires these contract addresses:

| Contract              | Description                             | Required for ciphernode |
| --------------------- | --------------------------------------- | ----------------------- |
| `bracken`             | Main Bracken coordinator contract       | Yes                     |
| `ciphernode_registry` | Tracks registered operators             | Yes                     |
| `bonding_registry`    | Manages bonds and tickets               | Yes                     |
| `slashing_manager`    | Manages slashing penalties              | Yes                     |
| `e3_program`          | E3 Program contract address             | No                      |
| `fee_token`           | Fee token address for E3 requests       | No                      |
| `faucet`              | Testnet faucet for BRACKEN + fee tokens | No                      |

Each contract can be specified as a simple address string or with a deploy block for faster syncing:

```yaml
contracts:
  bracken:
    address: '0xB2719FBF71F723FAb7fEAa1f3D2B6F23530AeE12'
    deploy_block: 45075164
  ciphernode_registry: '0x7d6e460B1704B5B1cd5570E62a3c450a9611C346'
```

Giving a `deploy_block` lets the node start its log scan there instead of at genesis, which on a
chain this size is the difference between minutes and hours.

<Callout type='info'>
  There is no faucet on Robinhood Chain. The `faucet` key exists for test deployments that have one;
  leave it out here.
</Callout>

## Networking Requirements

### Firewall Configuration

Open the following ports:

| Port   | Protocol | Purpose                    |
| ------ | -------- | -------------------------- |
| `9091` | UDP      | QUIC/libp2p P2P networking |

> **Important:** Port `50505` (TCP) is used for local CLI commands and binds to `localhost` only.
> **Do not expose this port externally** - it provides control plane access to your node.

### Bootstrap Peers

Connect to the Bracken bootstrap network:

```yaml
peers:
  - '/dnsaddr/bootstrap.bracken.network'
```

Or specify individual peers:

```yaml
peers:
  - '/dns4/node1.example.com/udp/9091/quic-v1'
  - '/ip4/192.168.1.100/udp/9091/quic-v1'
```

## Data Directories

| Directory                      | Contents                          |
| ------------------------------ | --------------------------------- |
| `~/.config/bracken/`           | Configuration files, network keys |
| `~/.local/share/bracken/`      | Databases, job data, keystores    |
| `~/.local/share/bracken/jobs/` | Per-E3 secret shares and state    |

> Back up these directories regularly. The `jobs/` directory contains encrypted key shares for
> active E3s - losing this data while participating in a committee may result in slashing.

## Monitoring

### Log Levels

Control verbosity with the `-v` flag:

| Flag   | Level | Description              |
| ------ | ----- | ------------------------ |
| (none) | WARN  | Warnings and errors only |
| `-v`   | INFO  | Normal operation logs    |
| `-vv`  | DEBUG | Detailed debug output    |
| `-vvv` | TRACE | Full trace logging       |

### Key Events to Watch

| Event                       | Meaning                              |
| --------------------------- | ------------------------------------ |
| `E3Requested`               | New computation request detected     |
| `TicketGenerated`           | Your sortition ticket was calculated |
| `CiphernodeSelected`        | You were selected for a committee    |
| `KeyshareCreated`           | Your key share was generated         |
| `PublicKeyAggregated`       | Committee public key is ready        |
| `CiphertextOutputPublished` | Time to generate decryption share    |
| `DecryptionshareCreated`    | Your decryption share was published  |
| `PlaintextAggregated`       | Final result is available            |
