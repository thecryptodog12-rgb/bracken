# Deploy your E3 to Robinhood Chain

<Callout type='info'>
  **Loxley is live on Robinhood Chain** (chain id `4663`). Any address shown inline below is an
  example unless it appears on [Deployments](/deployments) — that page is generated from the
  deployment record and is the one to configure against.
</Callout>

This tutorial takes you from a working local E3 (from [Quick Start](/quick-start) or CRISP) to the
live deployment on Robinhood Chain.

> **What you'll build:** your E3 program contract on chain 4663, a coordination server pointed at
> the Robinhood RPC, and an end-to-end E3 round against the live protocol contracts.
>
> **Prerequisites:** a working local E3, ETH on chain 4663 for gas, and a funded deployer key.

<Callout type='warning'>
  There is no committee yet. No ciphernode has bonded, so an E3 you request will sit at the
  sortition step until operators exist. You can deploy and wire everything up; you cannot yet get a
  result back. That is the honest state of the network, not a fault in this tutorial.
</Callout>

---

## 1. What you need on chain

- **ETH on chain 4663** for gas. The full protocol deploy cost about 0.0015 ETH; deploying a single
  program contract is a fraction of that.
- **USDG** for E3 fees and ticket collateral — `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`, six
  decimals. This is an existing token on the chain, not one this project issues.
- **LOXLEY** only if you intend to run a ciphernode — `0x12BE21fafF941622806b770a3a6c0aAEc23cff20`.
  Requesting computation does not need it.

There is no faucet. Every address is on [Deployments](/deployments).

## 2. Configure Environment

Create or update your `.env` file:

```bash
HTTP_RPC_URL=https://rpc.mainnet.chain.robinhood.com

# Deployer key. Keep it out of your shell history:
#   read -rs "PRIVATE_KEY?key: " && export PRIVATE_KEY
PRIVATE_KEY=0x...

CHAIN_ID=4663

# Live Loxley contracts on Robinhood Chain
LOXLEY_ADDRESS=0xB2719FBF71F723FAb7fEAa1f3D2B6F23530AeE12
CIPHERNODE_REGISTRY_ADDRESS=0x7d6e460B1704B5B1cd5570E62a3c450a9611C346
FEE_TOKEN_ADDRESS=0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168
```

## 3. Deploy Your E3 Program Contract

If you're deploying your own E3 program contract (not using an already-deployed one):

```bash
# From your project root
pnpm deploy:contracts --network sepolia
```

This uses Hardhat to deploy your contracts to Sepolia. Make sure `hardhat.config.ts` has the Sepolia
network configured:

```typescript
// hardhat.config.ts
networks: {
  sepolia: {
    url: process.env.HTTP_RPC_URL,
    accounts: [process.env.PRIVATE_KEY],
  },
}
```

Note the deployed contract address — you'll need it for the E3 request and the server config.

### Verify on Etherscan

Publishing source makes your contract inspectable and lets users interact with it from Etherscan's
UI. Set an Etherscan API key and run:

```bash
# .env
ETHERSCAN_API_KEY=your_key

# Verify
pnpm hardhat verify --network sepolia <YOUR_PROGRAM_ADDRESS> <constructor-arg-1> <constructor-arg-2>
```

Constructor args are whatever you passed to your program's constructor — typically the Loxley
contract address and any verifier addresses.

### Save the address

Persist the deployed address in `.env` so your server and frontend pick it up automatically:

```bash
# Append the fresh address — don't forget this step
echo "E3_PROGRAM_ADDRESS=<deployed_address>" >> .env
```

## 4. Switch to Secure BFV Parameters

On testnet, you should use the production BFV parameters. Update your SDK initialisation:

```typescript
const sdk = new LoxleySDK({
  // ... other config
  thresholdBfvParamsPresetName: 'SECURE_THRESHOLD_8192',
})
```

The SDK will automatically use the secure parameters when requesting E3s:

```typescript
const hash = await sdk.requestE3({
  committeeSize: CommitteeSize.Minimum,
  inputWindow: [startTime, endTime],
  e3Program: YOUR_PROGRAM_ADDRESS,
  computeProviderParams: '0x...',
  paramSet: 0, // Insecure,
})
```

Secure parameters use polynomials of larger degrees (N=8192 vs N=512) which makes proof generation
slower but provides real cryptographic security. Expect proof generation to take longer than in
local dev.

---

## 5. Configure the Server

Update your coordination server to point to Sepolia:

```bash
# .env for the server
HTTP_RPC_URL=https://rpc.mainnet.chain.robinhood.com
LOXLEY_ADDRESS=0xB2719FBF71F723FAb7fEAa1f3D2B6F23530AeE12
E3_PROGRAM_ADDRESS=<your deployed program address>
CHAIN_ID=4663
```

Start the server:

```bash
pnpm dev:server
```

The server will connect to Sepolia via WebSocket and begin listening for E3 events.

## 6. Test End-to-End

1. **Request an E3** — via the SDK or your frontend
2. **Wait for committee formation** — the Sepolia ciphernode committee will perform sortition and
   DKG (this takes longer than local dev due to real block times)
3. **Submit encrypted inputs** — your frontend encrypts under the threshold public key and submits
4. **Wait for computation** — the compute provider runs the FHE program
5. **Check the result** — the committee decrypts and publishes the plaintext

Monitor progress by watching for events:

```typescript
sdk.onLoxleyEvent(LoxleyEventType.E3_REQUESTED, (e) => console.log('E3 requested'))
sdk.onLoxleyEvent(RegistryEventType.COMMITTEE_PUBLISHED, (e) => console.log('Committee ready'))
sdk.onLoxleyEvent(LoxleyEventType.CIPHERTEXT_OUTPUT_PUBLISHED, (e) => console.log('Output ready'))
sdk.onLoxleyEvent(LoxleyEventType.PLAINTEXT_OUTPUT_PUBLISHED, (e) => console.log('Result:', e.data))
```

## Troubleshooting

| Issue                       | Possible cause                              | Fix                                                                        |
| --------------------------- | ------------------------------------------- | -------------------------------------------------------------------------- |
| E3 request reverts          | Insufficient fee token approval             | Call `sdk.approveFeeToken()` first                                         |
| Committee never forms       | Not enough active ciphernodes on Sepolia    | Check the registry for active operators                                    |
| Proof generation fails      | Missing circuit artifacts for secure preset | Ensure `secure-8192` artifacts are built                                   |
| Decryption produces garbage | BFV preset mismatch                         | Verify both SDK and E3 request use `SECURE_THRESHOLD_8192` / `paramSet: 1` |
